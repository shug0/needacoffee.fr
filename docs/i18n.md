# Internationalization (i18n) Setup

This project uses a custom internationalization system compatible with Next.js App Router.

## Structure

```
├── locales/
│   ├── en.json          # English translations
│   └── fr.json          # French translations
├── lib/
│   └── i18n-app.ts      # App Router compatible translation utilities
├── components/
│   └── ui/LanguageSwitcher.tsx  # Language switcher component
└── app/
    ├── layout.tsx       # Root layout
    └── page.tsx         # Home page with translations
```

## Configuration

This project uses a custom i18n system that works with the App Router. No configuration is needed in `next.config.ts`.

## Usage

### Using translations in components

```typescript
import { useTranslation } from "../lib/i18n-app";

export default function MyComponent() {
  const { t, locale, changeLocale } = useTranslation();

  return (
    <div>
      <h1>{t("home.title")}</h1>
      <p>{t("home.description")}</p>
      <button onClick={() => changeLocale("fr")}>Switch to French</button>
    </div>
  );
}
```

### Translation keys

Translation keys use dot notation to access nested objects:

```json
{
  "home": {
    "title": "Welcome to NeedACoffee",
    "subtitle": "Your perfect coffee companion"
  }
}
```

Access with: `t('home.title')` → "Welcome to NeedACoffee"

### Adding new translations

1. Add the key to both `locales/en.json` and `locales/fr.json`
2. Use the key in your component with `t('your.key')`

### Language Switcher

The `LanguageSwitcher` component provides a button to change languages:

```typescript
import LanguageSwitcher from "../components/ui/LanguageSwitcher";

// Use in your layout or pages
<LanguageSwitcher />;
```

## Available locales

- **French (fr)**: Default language
- **English (en)**: Secondary language

## URL Structure

With the custom i18n system, URLs include the locale:

- French: `/` (default)
- English: `/en/`

## Adding new locales

1. Create a new translation file in `locales/`
2. Update the `lib/i18n-app.ts` file to include the new locale
3. Update the `LanguageSwitcher` component if needed
4. Add the new route in the App Router structure

## Best Practices

1. Always provide fallback translations in French
2. Use descriptive key names that reflect the content
3. Group related translations under common namespaces
4. Test translations with different text lengths
5. Consider right-to-left (RTL) languages if needed in the future
6. Use the App Router compatible `useTranslation` hook from `lib/i18n-app`
